# SSH: Connecting to HPC and Using VS Code Remotely

本文介绍 SSH 的基本概念、从本地终端登录超算，以及使用 VS Code 连接远程服务器。不同超算的主机名、端口、认证方式和使用规定可能不同；请以所在机构或集群的官方文档为准。文中的 `用户名`、`登录节点`、`端口` 和路径均为占位内容，需要替换成实际信息。

## 什么是 SSH

SSH（Secure Shell）是一种通过加密连接远程计算机的网络协议。连接建立后，可以在本地终端远程执行命令、管理文件，或运行支持 SSH 的远程开发工具。SSH 通常使用 TCP 端口 `22`，但超算也可能指定其他端口。

SSH 常见的认证方式包括：

- **密码或多因素认证**：按集群要求输入密码、验证码或通过身份验证系统确认。
- **SSH 密钥**：本地生成一对密钥。私钥留在本地设备，公钥按集群规定登记在远程账户中。登录时使用私钥证明身份。

> **安全提示：** 不要把私钥发送给他人、上传到代码仓库或复制到超算上。不要在未核实服务器指纹时接受首次连接提示；请通过集群官方文档或管理员核对指纹。

## 连接超算前的准备

从超算官方文档或管理员处确认以下信息：

| 信息 | 示例格式 | 说明 |
|---|---|---|
| 用户名 | `your_username` | 超算账户名，通常不同于本机用户名 |
| 登录节点 | `login.example.edu` | 供用户登录和提交作业的入口节点 |
| SSH 端口 | `22` | 若未特别说明，通常为 `22` |
| 认证方式 | 密码、MFA 或 SSH 密钥 | 按集群要求配置 |
| 网络要求 | 校园网、VPN 或跳板机 | 有些集群不能从公网直接访问 |

超算可能要求先连接校园网或 VPN，也可能要求通过跳板机（bastion/jump host）进入。请只使用管理员提供的连接方式，不要自行猜测节点名称或端口。

## 从终端连接

在 macOS 或 Linux 上打开 Terminal；在 Windows 上可使用 PowerShell、Windows Terminal 或其他支持 OpenSSH 的终端。执行：

```bash
ssh 用户名@登录节点
```

例如，形式上可能类似：

```bash
ssh your_username@login.example.edu
```

如果集群使用非默认端口：

```bash
ssh -p 端口 用户名@登录节点
```

首次连接时，SSH 可能会显示服务器主机密钥指纹并询问是否继续。先与官方公布的指纹核对；确认一致后才输入 `yes`。之后根据集群配置完成密码、MFA 或密钥认证。成功登录后会出现远程 shell 提示符，可以运行集群允许的命令。

### 使用 SSH 密钥（按集群要求配置）

若集群支持密钥登录，可在**本地电脑**生成一对 Ed25519 密钥：

```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```

按提示选择密钥保存位置，并为私钥设置口令。默认文件通常为 `~/.ssh/id_ed25519`（私钥）和 `~/.ssh/id_ed25519.pub`（公钥）。

只向集群提交公钥 `id_ed25519.pub`，并按官方说明登记。**不要复制或上传没有 `.pub` 后缀的私钥文件。** 如果集群要求在账户门户登记公钥，应使用门户，而不是尝试自行修改远程 `authorized_keys`。

如果密钥保存在默认位置，连接命令通常不变：

```bash
ssh 用户名@登录节点
```

若管理员提供了特定私钥路径，可显式指定：

```bash
ssh -i ~/.ssh/密钥文件 用户名@登录节点
```

### 配置 SSH 别名（可选）

可以在本地的 `~/.ssh/config` 添加主机别名，之后使用较短的命令连接：

```text
Host my-hpc
    HostName 登录节点
    User 用户名
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 60
```

将 `HostName`、`User` 和 `Port` 替换为集群提供的信息；如果使用密码或 MFA，或集群对密钥有其他要求，请相应调整配置。保存后可运行：

```bash
ssh my-hpc
```

如果连接需要跳板机，应只在确认官方连接方案后配置 `ProxyJump`，并使用管理员提供的跳板机地址。

## 使用 VS Code 连接远程服务器

VS Code 的 **Remote - SSH** 扩展通过 SSH 连接远程主机，并在远程端启动 VS Code Server。编辑和终端操作可以直接针对远程文件；计算和作业仍应遵守超算的资源使用规定。

1. 在本地 VS Code 的扩展面板中搜索并安装 Microsoft 的 **Remote - SSH** 扩展。
2. 确认在本地终端中已能成功运行 `ssh 用户名@登录节点`，或已配置 `~/.ssh/config` 中的主机别名。
3. 在 VS Code 中打开命令面板：
   - macOS：`Cmd+Shift+P`
   - Windows/Linux：`Ctrl+Shift+P`
4. 选择 **Remote-SSH: Connect to Host...**。
5. 选择已有主机（例如 `my-hpc`）；如果还没有配置，可选择添加新的 SSH 主机，并按提示输入连接命令和保存配置文件。
6. 首次连接时，按提示确认主机平台，并完成 SSH、密码或 MFA 认证。首次连接可能需要一些时间来安装远程端的 VS Code Server。
7. 连接成功后，在远程窗口中选择 **File > Open Folder...**，打开超算上的项目目录。

打开远程终端（**Terminal > New Terminal**）后，终端命令会在远程主机上执行。VS Code 扩展可能需要分别安装到本地或远程端；请按扩展面板提示选择安装位置。

### 超算使用注意事项

- **登录节点通常不是计算节点。** 请查看集群规定；不要在登录节点上运行长时间、高 CPU/GPU 或高内存的计算任务。
- 通常应在登录节点编辑文件、准备输入并通过调度系统提交作业；实际计算在获批的计算节点上运行。
- 有些集群不允许 VS Code Server 长时间运行在登录节点，或要求通过专用开发节点、交互式作业连接。遇到此类规定时，使用集群提供的方案。
- 远程窗口显示已连接，并不表示已分配计算资源，也不代表作业正在运行。
- 离开前保存文件；关闭窗口或断开连接不会自动取消已提交的作业。作业状态和取消方式请参照集群的调度系统文档。

## 常见问题

### `Permission denied`

检查用户名是否正确、账户是否已启用、认证方式是否符合要求，以及密钥公钥是否已按集群流程登记。若使用密钥，可在本地检查文件权限和 `IdentityFile` 路径；不要把私钥发给他人寻求排查。

### `Could not resolve hostname` 或连接超时

检查主机名和端口是否正确，并确认当前网络是否满足集群要求（例如需要校园网或 VPN）。也可能是集群维护或网络策略阻止了连接；必要时联系管理员。

### VS Code 连接失败

先确认相同主机别名能在本地终端通过 SSH 登录，再检查 VS Code 的 Remote - SSH 输出日志。若集群限制登录节点上的常驻进程、远程安装或交互式连接，请按集群文档使用其支持的工作流。
